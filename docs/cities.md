# 市区町村マスタ

`data/cities.json` は日本の全市区町村と、その代表点（緯度経度）の表。整備計画マップ（`docs/plan-map.md`）が 3 つの用途で使う。

- **座標のフォールバック** — `data/plans.json` の `lat` / `lng` が `null` のレコードを、この代表点で地図に出す
- **所在地の語彙** — `npm run plan` はこの表にある `pref` / `city` しか台帳に書かせない
- **レコード順** — 配列の並び（＝全国地方公共団体コード順）が、台帳と地図のソート順を決める

この表は別のパイプラインで再生成され、台帳がそれに従う。

## データ元

デジタル庁 **アドレス・ベース・レジストリ (ABR)** の 2 ファイル。`lg_code`（全国地方公共団体コード）で結合する。

| ファイル | 内容 |
|---|---|
| [`mt_city_all.csv.zip`](https://data.address-br.digital.go.jp/mt_city/mt_city_all.csv.zip) | 市区町村コード・都道府県名・郡名・市区町村名・政令市区名・効力発生日・廃止日 |
| [`mt_city_pos_all.csv.zip`](https://data.address-br.digital.go.jp/mt_city_pos/mt_city_pos_all.csv.zip) | 代表点の緯度経度 |

**代表点は市区町村役場の位置**。千代田区は千代田区役所、稚内市は稚内市役所、檜原村は檜原村役場に一致する。

ダウンロード URL が変わったときは、レジストリのカタログ API から現在のリンクを引ける。

```
https://dataset.address-br.digital.go.jp/api/search/v1/collections/all/items/{id}
```

## 表の内容

**その日に実在する市区町村**を、全国地方公共団体コード順に並べる。ABR は合併・改称を発効前から載せるが、この表は発効日が来るまで前の姿を保つ — 先取りすると、まだ存在する市区町村を台帳が名指しできなくなる。

政令指定都市は**市の単位**で持つ（`浜松市天竜区` ではなく `浜松市`）。東京 23 区は上位に市を持たない基礎自治体なので、23 件そのまま載る。

レコードは 5 列。

| 列 | 内容 |
|---|---|
| `code` | 全国地方公共団体コード。6 桁の文字列 |
| `pref` | 都道府県名 |
| `city` | 市区町村名。郡名を含む（`上伊那郡箕輪町`） |
| `lat` / `lng` | 代表点の緯度経度 |

**1 レコード 1 行で書く。** 再生成の差分は「どの市区町村が変わったか」がすべてで、1 行に minify すると「150KB の 1 行が置き換わった」としか読めず、レビューも履歴を追うこともできない。

## 再生成

```bash
npm run generate:cities
```

`data/cities.json` を書き、続けて `data/plans.json` を新しい表に追随させ、何が変わったかを報告する。

**⚠️ 日本国内から実行すること。** ABR の配信は CloudFront で地域制限がかかっており、国外からは 403 が返る（`The Amazon CloudFront distribution is configured to block access from your country.`）。GitHub Actions のランナーは国外なので、**自動実行はできない**。

実行のタイミングは人が決める。ABR の市区町村マスタは年数回しか変わらないので、市町村合併・改称のニュースを見たときと、`plans.json` の調査で `Unknown municipality` に当たったときが目安になる。

## `data/plans.json` の追随

市区町村が変わると台帳のレコードが孤児になる。確度で 2 段に分けて扱う。

- **改称（`lg_code` が同じまま名前が変わった）** — 自動で書き換える。コードが一致するので誤りようがない
- **合併・分割（コードごと消えた）** — 後継が一意に決まらないので**書き換えない**。`npm run plan -- update` のコマンド行を報告するので、メンテナが調べて直す

自動で直すときは **`checked_on` を更新しない**。あれは「最後に調査した日」で調査キューの並び替えキーであり、自治体が名前を変えたことは調査の事実を何も意味しない。

孤児が残ったままでも生成は止まらない。報告が手元に出て、コミットすれば CI が落ちる。
