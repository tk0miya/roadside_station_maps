# 道の駅 整備計画の発見

台帳 `data/plans.json` にまだ無い道の駅の計画を都道府県単位で探し、見つけた計画を深掘りしてレコードとして追加する。

## 全体の流れ

0. 作業ツリーを整える — 未コミットの変更がないことを確かめ、`origin/master` から作業用のブランチを切る
1. 検索予算で対象の県を決める — `data/discovery.json` のキューを古い順に取る
2. 県ごとにサブエージェントで探して深掘りする
3. 台帳に書く
4. 調べ終えた県をキューに記録する
5. コミットして PR を出す
6. 締めにキューの残りを報告する

番号は以降の節に対応する。

**始める前に `docs/plan-map.md` と `.claude/skills/michi-no-eki-plan-research/SKILL.md` の §2 を読む。** 列の意味、出典の格、値の書き方（`date` を丸めない、`status` を動かす条件、`city` の表記、不適切な出典サイト、PDF の読み方）はそこにあり、このスキルでもそのまま従う。ここに書くのは発見に固有のことだけ。

## 0. 作業ツリーを整える

`michi-no-eki-plan-research` の §0 と同じ。**未コミットの変更があれば中断してメンテナに報告する。** クリーンなら `origin/master` の先端から切る:

```bash
git fetch origin &&
  git switch -c "claude/plan-discovery-$(TZ=Asia/Tokyo date +%Y%m%d-%H%M)" origin/master
```

**古い `master` から始めない。** 前回のセッションがキューを進めた `data/discovery.json` は `master` にあるので、古いまま §1 を撃つと前回と同じ県を引く。

## 1. 検索予算で対象の県を決める

### 予算

**WebSearch は 1 セッション 200 回が上限。このセッションの予算は 150 回とする。** 残りの 50 回は見積もりのぶれの吸収に取っておく — 上限に当たると、そこまでの調査が書き込まれないまま止まる。

サブエージェントの検索もこの予算に数える（上限がサブエージェントごとに数えられるのかは確かめられていないので、安全側に倒す）。**親（このセッション本体）は検索しない。** 検索はすべてサブエージェントに割り当てた予算の中で行う。

県ごとの割り当て:

| 県 | 割り当て |
|---|---|
| 北海道 | 50 回 |
| それ以外 | 25 回 |

北海道だけ倍なのは市町村数が桁違い（179）だから。

### 県を取る

キューを古い順に読み、**割り当ての合計が 150 を超えない範囲で先頭から取る。** 途中の県を飛ばして後ろの県で埋めない — 飛ばした県がキューの先頭に居座り続ける。

```bash
npm run --silent plan -- discovery list | jq -r '.[] | [.discovered_on, .pref] | @tsv'
```

並びは `discovered_on`（最後に発見を回した日、JST）の古い順で、同じ日なら都道府県コード順。

**県を指定されたときは、キューではなくその県を調べる。** 予算 150 回は同じ。収まらない県は次のセッションに回し、最終応答に列挙する。

## 2. 県ごとにサブエージェントで探して深掘りする

**1 県 1 サブエージェントで、全県ぶんを並列に起動する。** 検索結果とページ本文はサブエージェントの中で読み捨て、親に返ってくるのは候補の一覧だけにする — 親のコンテキストは §3 の書き込みに使う。

**サブエージェントは台帳を書き換えない。** 書くのは親だけ（§3）。並列に `npm run plan` を撃つと、同じファイルを読み書きして互いの変更を消す。

### 渡すもの

起動の前に、県ごとに次を集めてプロンプトに入れる:

```bash
# その県の台帳のレコード（重複して報告させないため）
npm run --silent plan -- list | jq -r '.[] | select(.pref == "熊本県") | [.name, .city, .status] | @tsv'
# その県の前回の発見日
npm run --silent plan -- discovery list | jq -r '.[] | select(.pref == "熊本県") | .discovered_on'
```

### プロンプトのひな形

`{…}` を埋めて渡す。**検索回数の上限と、使った回数を報告させることは必ず残す。**

````markdown
台帳 data/plans.json にまだ載っていない「道の駅」の計画を Web 検索で見つけ、見つけたものを深掘りしてください。対象は {pref} です。今日は {today}。この県を前回調べたのは {discovered_on} です。

リポジトリ: {repo の絶対パス}
**WebSearch は最大 {budget} 回まで。** 超えそうなら、そこで探索をやめて分かった範囲で報告すること。WebSearch / WebFetch は ToolSearch（"select:WebSearch,WebFetch"）でロードする。
**ファイルは書き換えないこと**（`npm run plan` の書き込み系コマンドも撃たない）。報告は親が台帳に書く。

まず `.claude/skills/michi-no-eki-plan-research/SKILL.md` の §2（「既存の道の駅と取り違えない」〜「書く値: urls」）と `docs/plan-map.md` の「出典を選ぶ」を読み、値の決め方と出典の選び方をそれに合わせること。

## 対象
- 新設の計画、既存駅の移転、建て替えや全面改修などの大規模な再整備
- 対象外: 売店の改装程度の改修、既に開業したもの、中止・断念が宣言されたもの

## 台帳に既にあるもの（報告不要）
{その県の台帳のレコード: name / city / status}

仮称（「道の駅 ◯◯町」）と正式名称で同じ計画を指していることがある。所在地と内容で突き合わせ、同じ計画なら新規として報告しない。ただし、その計画について台帳より新しい情報（登録・開業日決定・改名・中止宣言など）を出典付きで見つけたら「既存レコードの新情報」として報告する。それを探すために検索を使う必要はない。

既存の開業済みの駅は `grep "{pref}" data/stations.geojson` で引ける（1 行 1 駅、座標は [lng, lat]）。

## 進め方
1. 探索（予算の 4 割程度まで）: 県全体を広く引くクエリから始め、引っかかった市町村で絞り込む。WebSearch は `after:` を解釈しないので、新しい記事を拾うには年号をクエリに入れる。
   - `{pref} 道の駅 新設 整備 基本計画 {今年}` / `"道の駅" 基本構想 {pref} 候補地 {昨年} {今年}`
   - `{pref} 道の駅 移転 再整備 建て替え {今年}`
   - `{地方紙名} 道の駅 新設 計画 {今年}`
   - 市町村で絞るとき: `{city（郡名を除く）} 道の駅 整備 基本計画`
   前回（{discovered_on}）以降の記事を優先して読むが、それ以前の記事でも台帳に無い計画なら候補にする。
2. 深掘り（残りの予算）: 候補ごとに 5 回程度までで、自治体の公式資料と地方紙を当たり、下の報告項目を埋める。記事の日付は開いて確かめる。予算が尽きたら、出典 1 本を開いて計画の存在を確かめた候補はそこまでの内容で報告する。

## 報告（候補ごと）
- 名前: 正式名称・愛称があればそれ、なければ仮称「道の駅 ◯◯町」。移転・再整備なら台帳の既存の書式に倣って `道の駅 ◯◯ (移転)` / `道の駅 ◯◯ (再整備)`
- 所在地: `data/cities.json` にある表記の city（郡名を含む。政令市は市まで）
- status: 計画中 / 登録済み（国交省に登録済みで未開業）/ 凍結
- date: 開業予定。出典の表現そのまま（和暦→西暦だけ変換。「令和9年度」→「2027年度」）。不明なら空
- 座標: 現在地での再整備なら stations.geojson の既存駅の座標。移転・新設は、出典が示す予定地から確定できる場合だけ。推測で埋めない
- 出典: 実際に開いて中身を確かめた URL と、そのページの見出し（最大 3 本、強い順）
- 判断に迷った点（所在地が資料で食い違う、など）

最後に必ず: **使った WebSearch の回数**、候補が無かったならそう書く。推測で埋めないこと。
````

## 3. 台帳に書く

サブエージェントの報告が揃ったら、親が 1 件ずつ書く。書き方は `michi-no-eki-plan-research` §2 の「レコードを追加する」「書く値: …」のとおり。

**書く前に重複を親の目でも確かめる。** サブエージェントには台帳を渡してあるが、仮称と正式名称の取り違えは起きる:

```bash
npm run --silent plan -- list | jq -r '.[] | select(.pref == "熊本県") | [.name, .city, .status] | @tsv'
```

```bash
npm run plan -- add --name='道の駅 球磨村' --pref=熊本県 --city='球磨郡球磨村' --status=計画中 \
    --date=2030年度 --url='https://example.jp/news' --title='球磨村に道の駅を整備へ'
# 2 本目以降の出典
npm run plan -- url add '道の駅 球磨村' 熊本県 --url='https://example.jp/plan' --title='道の駅整備基本計画'
```

座標が報告されていれば `--lat` / `--lng` に渡す。無ければ省略する（`city` の代表点に落ちる）。

**「既存レコードの新情報」は、出典があって research スキルの基準を満たすものだけ反映する。** 満たさないもの（疑いの段階の中止など）は書かない。

列に書けないこと（所在地が資料で食い違うなど）は、research スキルと同じく `docs/plan-reports.md` の末尾に追記する。

書き終えたら `git diff data/plans.json` で、意図したレコードだけが動いていることを確かめる。

## 4. 調べ終えた県をキューに記録する

**サブエージェントが報告を返した県だけ** 記録する。候補が 0 件だった県も記録する（調べた結果「無い」ことが分かった）。

```bash
npm run plan -- discovery done 熊本県
```

**報告が返らなかった県（エラー・途中終了）は記録しない。** 記録するとキューの最後尾に回り、調べていないのに一周先まで引かれなくなる。

## 5. コミットして PR を出す

```bash
npm run lint:fix
npm test
```

**1 セッション 1 PR。** `data/plans.json` と `data/discovery.json`（と追記したなら `docs/plan-reports.md`）を 1 コミットにまとめる。コミットログは英語で、「何を変更したか」と「その結果何が達成されたか」を書く。

```bash
git push -u origin HEAD
```

PR 本文に書くのは 3 つだけ:

1. **調べた県** — 県ごとに使った検索回数と、追加した件数（0 件も書く）
2. **座標を入れられなかった追加レコード** — メンテナが地図で位置を確かめて埋めるため
3. **報告事項** — `docs/plan-reports.md` に追記した内容

追加・更新したレコードの中身は書かない。差分と `urls` に出ている。

## 6. 締めにキューの残りを報告する

最終応答には次を書く:

- **キューの状態** — 全件書き終えてから数える:

  ```bash
  npm run --silent plan -- discovery list \
    | jq '(.[0].discovered_on) as $oldest
          | {oldest: $oldest, at_oldest: ([.[] | select(.discovered_on == $oldest)] | length)}'
  ```

  > いちばん古い発見日は YYYY-MM-DD で ◯◯ 県。

- **持ち越した県** — 名指しされて予算に収まらなかった県、報告が返らず記録しなかった県
