# 駅ごとの調査と、書き込む値の決め方

道の駅 1 件について Web で最新情報を集め、シートに書く値を決めるための手順。担当分の駅それぞれについてこれを行う。

**調査を任されたサブエージェントとしてこれを読んでいる場合、書き込みは行わない。** `plan:update` は実行せず、調べた結果を返すところまでを担当する。更新は結果を受け取った側が、ユーザーの承認を得てから行う。

## 検索クエリの組み立て

**`city` から郡名を除去する。** 郡名を含めると検索がヒットしない。

- `上伊那郡箕輪町` → `箕輪町`
- `高岡郡佐川町` → `佐川町`
- `さいたま市岩槻区` → そのまま（政令市の区は地名として機能する）

**`pref` を必ず含める。** 市町村名だけだと同名地名を拾う（「白石市」の検索で札幌市白石区が上位に来る）。

**`name` が仮称でなければ `name` で検索する。** 「道の駅 ◯◯市」「道の駅 ◯◯町」の形は仮称なので `city` で検索する。「みのわテラス」「くるん熊谷」のような固有名は、それ自体で検索した方がはるかに精度が高い。

```
道の駅 {pref} {city} 開業        ← 仮称の場合
{name} 開業 いつ                  ← 固有名がある場合
```

## 既存の道の駅と取り違えない

1 つの市区町村に道の駅が複数あることは珍しくない（南房総市には 8 駅、高山市にも 8 駅ある）。検索すると、その市区町村に既にある駅の記事が上位に来る。

調べているのは**新設・再整備の計画**なので、既存駅の話だと分かれば読み飛ばす。担当分の市区町村にどんな駅があるかを、調査を始める前に引いておく:

```bash
grep "南房総市" data/stations.csv | cut -f3   # リポジトリルートで実行する
```

`data/stations.csv` は michi-no-eki.jp のスクレイピング結果（拡張子に反して TSV）で、既存駅を引く用途に使う。**ただし登録済みかどうかの判定には使えない。** 登録されても掲載が遅れることがあるので、載っていないことは未登録の根拠にならない。

地名が似た別の駅が紛れ込むこともある（南アルプス市を調べると、長野県伊那市の「南アルプスむら長谷」が出てくる）。判断に迷ったら所在地と開業時期を見る。既に開業している駅の記事なら、調査対象ではない。

## 記事の日付は自分で確かめる

検索結果は新しい順には並ばず、数年前の記事が最上位に来る。**WebSearch は `after:` などの検索演算子を解釈しないので、クエリ側で期間を絞ることはできない。**

**開いて日付を確認してから判断の材料にする。** 古い記事しか出てこなければ「進捗なし」の根拠になる。日付が書かれていないページ（まとめサイトに多い）はいつの情報か分からないので、根拠にしない。

## 出典の優先順位

1. **自治体の公式サイト** — 一次情報。ただし更新が遅く、決定済みの情報が載っていないこともある
2. **地方紙・地方建設業紙** — 開業日の速報はここが早い。優先交渉権者の決定なども載る
3. **国交省・地方整備局** — 登録の確定情報
4. まとめサイト・個人ブログ — 古い情報が残りがちなので、他に裏が取れないときの補助に留める

## 自治体ページの中身は PDF のことが多い

一覧ページを開いても概要しか書いておらず、日程は添付 PDF にある、というパターンが頻出する。ページを WebFetch して「添付 PDF へのリンクを URL ごと列挙して」と指示すればリンクを拾える。

Bash のサンドボックスは許可ホストにしかネットワークを通さないので、`curl -s "<url>" | grep -oE 'href="[^"]*\.pdf"'` が通るとは限らない。試すのは自由だが、弾かれたら WebFetch に切り替える。

拾った PDF を WebFetch にかける。ただし**画像 PDF はこの環境ではテキスト化できない**（`pdftoppm` が入っていない）。読めなければ深追いせず、同じ内容を報じた記事を探す方が早い。

## date の決め方

シートは**判明している粒度をそのまま記録する**列で、`2026-09-18` も `2026` も `2026夏` も等しく正しい値。**変換してよいのは和暦 → 西暦だけで、それ以外は出典の言葉をそのまま写す。**

| 出典の表現 | 書く値 | |
|---|---|---|
| 令和 9 年 7 月オープン | `2027-07` | 月まで言い切っているので日付形式にできる |
| 令和 9 年度初頭 | `2027年度初頭` | ✗ `2027-04` — 「初頭」が何月かは出典が言っていない |
| 令和 9 年夏ごろ | `2027夏ごろ` | ✗ `2027-07` |
| 2028 年度 | `2028年度` | ✗ `2028` — 年度は 2029 年 3 月まで含む |
| 2026 年度下半期 | `2026年度下半期` | ✗ `2026` — 暦年をまたぐ |

「初頭」「上半期」「ごろ」を月に置き換えるのは、出典にない情報を足す行為で、**後から見たときに確定情報と区別がつかなくなる**。これがこの列でいちばん避けたい壊れ方なので、粒度を上げる方向にも下げる方向にも丸めない。

地図は `date` をパースせず値の有無しか見ていない（`src/frontend/types/plan.ts`）ので、日本語混じりの表記で壊れるものはない。

年度と暦年の区別だけは意識しておく — 「令和 9 年度」は 2027 年 4 月〜2028 年 3 月であって 2027 年ではない。ただし気づいたからといって暦年に直すのではなく、年度のまま書く。

### 開業が近いものは「延期」を疑う

`date` が 1〜2 年以内のレコードでは、**開業日が前倒しで確定するより延期される方が多い**。自治体は延期を「開業時期の延期について」のような専用ページで公表するので、既存の `date` を裏付ける情報だけで満足せず、より新しい発表がないか確認する。

延期の告知には「最終的な時期は◯月ごろ公表予定」と続きが予告されていることがある。見つけたら結果に含める — いつ再調査すべきかの判断材料になる。

## status の決め方

`計画中` / `登録済み` / `開業` / `中止` の 4 値のみ。

**登録は必ずニュースになる。** 国交省の登録は年 2 回（6 月・12 月）にまとまって公示され、登録証の交付は自治体の発表や地方紙の記事になる。自治体が「登録を目指す」と書いているだけでは `計画中` のまま。

`開業` への変更は、開業日が過ぎて実際に開いたことが確認できたときだけ。予定日を過ぎただけでは変えない（延期はよくある）。

## name の決め方

正式名称や愛称が判明したら変更を提案する（「道の駅 石川町」に対して正式名称が「道の駅石川」、仮称だった駅に「うぇるかぶ」のような愛称が決まった、など）。

**表記は出典の正式名称をそのまま写す。** `date` と同じ考え方で、シートの体裁に合わせて空白を足したり削ったりしない。ただし `(移転)` `(再整備)` はシート独自の区別で正式名称の一部ではないので、改名しても残す。

## memo に足す URL の選び方

出典 URL を改行区切りで並べた列。基準は「後から根拠を辿れるか」で、同じことを言っている記事を何本も足す必要はない。

## 気づいたデータの不備も返す

調査のついでに `pref` / `city` の誤り（所在地が実際と違う）や、既存 `memo` の URL が 404 になっていることに気づいたら、それも結果に含める。これらは調べた本人にしか見えないので、報告に上げないと誰も気づかない。

## 新しい情報がなかった駅も名前と都道府県を返す

既存の値を変える材料が出てこなかった駅は、**`name` と `pref` を列挙して返す**。理由は書かなくてよい。ユーザーへの報告には載らないが、集約側はこの一覧で「調査が済んだ駅」を特定する（調査済みの印をシートに書くのは集約側の担当で、返ってこなかった駅は調べていないものとして次回に回される）。だから**担当した駅は結果が空振りでも省かない。**

ただし `pref` / `city` の誤りやリンク切れに気づいた駅は、更新の材料がなくてもその不備を添える。不備は更新の有無とは関係なく見つかる。
